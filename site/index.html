URL in. Findings, evidence and fixes out.

A deterministic engine that observes a website the way a visitor who has not yet decided sees it, and reports what it saw against GDPR, ePrivacy and the AI Act. Passive, reproducible, verifiable.

Get startedSource on GitHub

What makes it different

Only what was observed

A finding comes from something the engine saw. A failed read never becomes an absence, and nothing is reported as passed that was not checked.

Reproducible evidence

The JSON result carries digests of the observation and the configuration. scanprivacy verify recomputes them.

Legitimate requests only

It reads from the entry page, honours robots.txt, never requests state-changing URLs, limits itself to one page load per second per host, and names its operator in the User-Agent.

Reports people can use

PDF and Markdown in English and Italian, with remediation per finding, an Art. 30 style recipient inventory, SARIF for code scanning and signed attestations.

Use it

pip install -e .
python -m playwright install chromium
scanprivacy scan https://example.org --pages 5 --pdf report.pdf --json evidence.json
scanprivacy verify evidence.json

In CI

- uses: fabriziosalmi/scanprivacy@v1
  with:
    url: https://www.example.org
    fail-on: critical

Run it as a service

docker build -t scanprivacy .
docker run --rm -e SCANPRIVACY_API_KEY=... -p 127.0.0.1:8099:8099 scanprivacy

It refuses to listen beyond loopback without an API key, because every request it makes reaches third parties in your name.

Scope and honesty

This is an observation tool, not legal advice or a certification. It sees one vantage point, one moment, and a visitor who has made no choice. The README lists its known limits.

An online scanner is planned after a dedicated hardening phase. Until then, run it yourself: it is open source.
