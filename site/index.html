Open source privacy conformance engine

What a website does before the visitor says yes.

scanprivacy loads a page the way a first-time visitor would and records every request, cookie and storage write. It reports what it saw against GDPR, ePrivacy and the AI Act, and every finding carries the evidence behind it. It never clicks, logs in or accepts anything.

git clone https://github.com/fabriziosalmi/scanprivacy
cd scanprivacy
pip install -e .
python -m playwright install chromium
scanprivacy scan https://example.org --pdf report.pdf --json evidence.json

How it observes

One visit, no choice
The page is loaded once, as a visitor who has neither accepted nor refused anything. What loads before that choice is what gets reported. The opt-in refusal pass is the only mode that touches a consent banner, and it writes a separate document.
Evidence first
Each finding lists the requests, cookies or headers that produced it, with steps to check it yourself using a browser and curl. A read that failed is a stated limit in the report, never an absence.
Polite by construction
It honours robots.txt, makes at most one page load per second to a host, never requests URLs that change state, and names its operator and a contact address in the User-Agent.
Reproducible
The JSON result carries digests of the observation and of the rules applied. scanprivacy verify recomputes them, and two results can be compared finding by finding with scanprivacy diff.

Evidence you can check

A report is a claim about a site at one moment. The JSON result next to it holds what was observed, and the digests in it let anyone confirm that the report describes that evidence and that the same rules were applied.

$ scanprivacy verify evidence.json
evidence intact    : yes
findings intact    : yes
  declared         : 923abf4d7fb19067…
  recomputed       : 923abf4d7fb19067…
ruleset unchanged  : yes
knowledge unchanged: yes

The example report on this site is made by the engine each time the site is built, and its evidence file is published next to it.

Limits, stated

  • It observes once, from one place. A single visit is a photograph: two loads of the same page can differ, and diff shows that variance instead of hiding it.
  • The default pass expresses no consent, so what a site does after acceptance is not verified. The refusal pass covers refusal only, for the consent platforms it knows.
  • A scan covers one deployment. Sibling hosts the entry page links to are listed in the page plan and not followed.
  • Text-based checks, such as the Art. 13 elements of a privacy notice, can miss an unusual wording, which is why those findings carry lower confidence.
  • It is not legal advice and not a certification.

Run it

In continuous integration

- uses: fabriziosalmi/scanprivacy@v1
  with:
    url: https://www.example.org
    fail-on: critical

As a service

docker build -t scanprivacy .
docker run --rm \
  -e SCANPRIVACY_API_KEY="$(python -c 'import secrets;print(secrets.token_urlsafe(32))')" \
  -p 127.0.0.1:8099:8099 -v scanprivacy-data:/data scanprivacy

It refuses to listen beyond loopback without an API key, because every request it makes reaches third parties in your name. Read Deployment before exposing it.
